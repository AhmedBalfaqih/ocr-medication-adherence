# System test log

This log holds the manual system test cases: at least one for each requirement from FR1 to FR15, plus the key non-functional requirements. Each case is run by hand in the browser, and its screenshot is saved in `screenshots/` under the test ID. Cases are added as each feature is built.

How to fill it in:

- The ID is `TC-`, the requirement and a number, for example `TC-FR6-01`.
- Actual and Result are filled in only after the case has been run. Result is Pass or Fail.
- A failed case is recorded as it happened, with the fix and the re-test.
- Every case uses the fictional demo accounts from `npm run db:seed`, or a made up account such as `new.patient@example.com`, never a real person's details or health data (DR5).
- The demo emails and passwords are in `.env`. The passwords are never written in this log.
- Label scan cases use a photo of a made up printed label or of a real medicine box. Never use a pharmacy sticker or any label with a person's name on it (DR5).
- The camera works only on a secure page, so the scan cases run on `http://localhost:3000` or on the production HTTPS address.
- Some devices show a time field on a 12 hour clock, such as 1:00 PM for 13:00. The times in these cases use the 24 hour clock, which is how the app saves and lists them.
- The reminder cases need the reminder check, `POST /api/cron/tick`, to run after a dose time has passed. On the production address, cron-job.org calls it every minute. On `http://localhost:3000` nothing calls it, so run the command under Run in the README each time a case waits for the check.
- Reminders by push work only on a secure page: `http://localhost:3000` on the same computer, or the production HTTPS address. Cases marked "Production address only" need a phone, a Mac or the cron-job.org job, so they run once the app is deployed.
- The reminder cases use the made up account `reminder.patient@example.com`, registered as in TC-FR1-01, with the made up medicine "Test Capsule" and the dose "20 mg", added as in TC-FR5-01. Its dose times are set a few minutes after the current time in Cairo, read from a world clock, with End date set to today unless the case says otherwise. Press Save dose times before the first of the new times comes: a time that has already passed when it is saved starts tomorrow (TC-FR10-05), so a slow save loses that dose for today. These cases run between 00:10 and 23:50 Cairo time.
- The dashboard cases with logged doses use the made up account `dashboard.patient@example.com`, registered as in TC-FR1-01, with "Test Capsule" and the dose "20 mg", added as in TC-FR5-01. Its doses become due the same way as in the reminder cases, so the notes above on the reminder check and the time of day apply to them too.
- The admin cases change and remove the made up account `managed.patient@example.com`, never the demo patient. It is registered as in TC-FR1-01 with the name "Managed Patient", with "Test Capsule" and the dose "20 mg" added as in TC-FR5-01 and one dose time at 08:00 every day added as in TC-FR9-01. The patient's side runs in a private window, so the patient and the admin are logged in at the same time. TC-FR14-05 removes the account and then creates it again, so run TC-FR14-01 to TC-FR14-05 in order, then TC-FR15-01. To run them again, add Test Capsule and its dose time to the new account first.
